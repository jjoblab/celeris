Simulateur interactif — les popups de celeris ADR-018 · 26 genres · feuilles modales

Chaque popup de l'éditeur, exactement comme le code la pose : mêmes sections, mêmes encres, mêmes régimes (frappe, défilement, tap hors cartes, échappement) — la machine à états réelle (PopupController) tourne ici en JavaScript. Cliquez une entrée du catalogue pour ouvrir la carte, bougez le curseur dans l'éditeur, jouez les commandes de régime ; la fiche de droite détaille l'utilisation de chaque surface.

Thème
Gabarit

Clavier vivant quand la scène a le focus : flèches, Entrée, Échap — l'éditeur délègue aux cartes (PIEGE-27). Le double-clic survole le symbole ; le glissement sélectionne.

  • PIEGE-27 — aucune carte ne prend le focus : l'éditeur le garde et délègue flèches, Entrée et Échap aux cartes ouvertes. Les feuilles modales, elles, prennent le focus (choix assumé, hors PIEGE-27).
  • ADR-018 — toute surface fonctionnelle est une popup : carte ancrée au curseur, feuille du bas ou feuille du haut ; jamais de dialogue système, jamais d'écran plein cadre.
  • La famille des surfaces d'actions — une surface d'actions à la fois : le menu d'intentions, le débordement de la toolbar, les gabarits, les cibles du déménagement et le masquage se chassent mutuellement ; les cartes qui décrivent (usages, hiérarchie, usages qui barrent) cohabitent avec la complétion.
  • Le montage hôte tient en trois gestes : new PopupsEditeur(editeur, session, couche, theme, tailleSp, coach), brancherServeur(...), puis les déclenchements maison — tout le reste vit déjà chez l'orchestrateur.
